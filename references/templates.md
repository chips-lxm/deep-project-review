# 本轮证据与任务模板

按需填写，不复制空表堆砌内容。模板中的字段是记录要求，取不到就写缺失及影响，不能虚填。

## 运行记录与覆盖矩阵

```text
run_id / 项目绝对路径或资源 ID：
本轮用户授权原文与来源：
审查范围 / 修改授权范围 / 禁止操作：
原始需求、用户约束、验收标准的原文或可读路径：
基准：HEAD / 修订号；staged / unstaged 差异；相关 untracked；文件哈希：
基准采集时间 / 当前成果版本 / 用户已有改动：
已有测试及其版本、实际结果；证据路径：
缺少材料与影响：
报告与隔离测试目录：
默认循环上限 2；已用轮数；用户预算调整：
```

| 需求/验收 ID | 原始材料 | 对应成果位置及版本 | 审查任务 | 实际覆盖 | 状态/证据 |
| --- | --- | --- | --- | --- | --- |

覆盖状态使用：已检查 / 未检查 / 无法验证 / 执行失败；“无问题”只描述已检查范围的发现情况，不能替代覆盖状态。


## 审查报告

```text
审查范围及对应版本：
实际检查过的内容：
未检查或无法验证的内容及原因：
执行失败情况（与无发现区分）：

发现的问题（可为空，并明确在已检查范围内未发现问题）：
- 问题编号（本轮唯一，例如 R2-003）
- 具体位置：文件/模块/页面/单元格/资源 ID；行号或区域；版本
- 对应需求或验收标准：ID、原文/证据位置
- 问题描述与影响：实际行为、期望行为、受影响对象
- 证据/复现步骤/验证方法：输入、环境、命令、输出路径、退出码
- 结论状态：已确认 / 待验证
- 严重程度及依据
- 建议的最小修复方向

已执行检查清单与实际结果：
```

严重程度建议：P0 = 阻断交付或严重安全/数据损失；P1 = 核心需求失效或重大影响；P2 = 局部功能/内容/计算错误；P3 = 轻微交付缺陷。按实际影响解释，不以主观偏好凑问题。严重度与确认程度分开，高严重度疑点仍可能待验证。

## Astra 复核记录

```text
复核任务与有效模型配置证据：
读取的原始需求、完整报告索引及各报告覆盖情况：
实际追溯的材料、计算路径、复现/测试证据：
遗漏范围、冲突与定向补查任务（若有）：

逐项：
- 统一问题 ID；所有原始问题 ID；重复项指向的主问题
- 分类：确认需要修复 / 建议优化 / 证据不足，待验证 / 不成立或重复
- 严重度及理由摘要；支持/反对证据；冲突处理依据
- 最小修复边界；禁止扩大范围；受影响模块与依赖
- 可操作验收标准、回归范围、所需证据

无确认问题时也说明实际复核范围及剩余限制。
```

## 修复回报与独立验收

```text
执行者回报：实际修改文件/对象、差异、版本；关联问题；实际验证；风险/未完成事项。

独立验收者：agent ID、模型配置证据；未参与该项修复的说明。
验收基准：修改后版本、用户并发变动核对。
原问题：复现方式；修复前/后结果与证据。
关联回归：功能、接口、数据、交付导出效果；实际结果。
测试逐项：已通过 / 失败 / 未运行 / 无法验证；命令、退出码、日志位置。
失败归因：基准已有 / 本轮新增 / 暂无法确定（附证据）。
重大/复杂/争议改动的 Astra xhigh 定向复核记录：
未满足验收项与下一步；是否进入下一轮（不得超上限）。
```

## 最终交付

```text
结论：本次已验证范围通过 / 仅审查完成 / 部分完成或受阻。
检查：项目版本、实际覆盖、未检查/无法验证/失败范围。
确认：Astra 四类问题清单及证据索引。
修改：实际修复与对应问题；只审查时写“未修改”并给具体修复计划。
验证：独立验收者、实际测试、回归、必要 Astra 定向复核。
遗留：问题、关键验收缺口、权限/模型/环境限制、轮数和下一步。
```
