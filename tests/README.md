# 验证方法

这些是 Skill 制作测试，不授权审查其他项目。测试智能体只读取本包与 cases.json，按案例作决策；代码片段仅在临时目录执行。禁止启动整套项目复审、递归委派或修改正式项目。

## 格式与资源

用 skill-creator 的 quick_validate.py 验证 frontmatter；以真正的 YAML/TOML 解析器读取配置，核对 implicit=false、显示名和 Astra ID/xhigh；检查包内 Markdown 相对链接可解析。该检查不证明语义或宿主触发。

## 独立行为前测

将 SKILL.md、相关 references 和 cases.json 交给 `fork_turns: none` 的真实子智能体，记录实际结构化配置及运行证据。不要提供预期答案或前一个评估者结论。

- 触发测试：对每个 T 案例返回“启动 / 不启动 / 入口未部署需显式调用”，说明用户授权、宿主是否能加载、是否有修改授权。只输出决策，不实际启动复审。natural_configured 仅是假设入口已加载后的语义测试，不是部署成功证据。
- 流程测试：对 W 案例返回可执行下一步、禁止动作、当前能声明的状态。W01 应实际执行给定代码片段、检查误报，记录退出码。其他案例是合成条件下的决策测试，不冒称发生过真实模型故障、项目修复或回归。
- 主会话依据用户制作要求核对输出，保留完整评估记录，修正发现的问题；失败后的定向重测必须有记录。

## 宿主端到端验收（单列状态）

安装后在隔离的新会话中，从技能选择器显式选取本 Skill，用 T01 验证宿主真正加载和进入授权门；不要直接注入 Skill 全文然后称为加载成功。普通、否定、引用与元讨论案例应只执行普通任务或解释，不创建审查智能体。

如需自然语言入口，先把 examples/AGENTS-entry.md 的规则及真实安装路径合并到隔离项目 AGENTS.md，再在新会话验证 T02、T03 及所有负例。未部署时 T04、T16 的可靠路径是提示显式调用，不声称自动加载。

完整流程测试需另行限定合成项目及写入范围，实际记录多审查者 → Astra xhigh → 修复 → 独立验收。测试不可用模型、失败测试和冲突时使用隔离夹具；不能为了测试人为删除真实项目材料。本次制作若只完成决策测试或调用探针，应明确将完整流程标记为未运行。

预期语义供维护者验收：T01/T13 允许只读启动；T02/T03 仅在入口已加载假设下允许启动；T04/T16 入口未部署；T05—T12/T14/T15/T18 不启动；T17 先明确项目且不得创建审查任务。工作流应排除 W01 误报、保留 W02 必需 Astra、W03/W04 报阻塞、W05 不给全面通过且缺少前后对照时不武断归因、W06 串行唯一负责人、W07 停在计划、W08 停止超预算、W09 重核对、W10 先核实合规入口且无写权限时停在计划、W11 按难度与预算路由、W12 独立验收。

## 实际宿主发现探针

`python3 tests/probe_discovery.py --cwd /隔离测试目录 --output /输出路径.json` 使用实际 Codex app-server 的 `initialize` 和 `skills/list`，只保存同名 Skill 的元数据，不发起模型回合、不启动复审。需要本机服务访问权限。它可验证宿主发现及中文元数据，不能验证入口语义、隐式排除是否实际生效或完整流程。
